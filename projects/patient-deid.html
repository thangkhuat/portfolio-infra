Case Study

Patient De-Identification Pipeline

An automated, auditable pipeline that redacts protected health information from clinical text against HIPAA's Safe Harbor standard — built to demonstrate secure operationalization of an existing detection engine, not novel PHI detection.

Python 3 boto3 AWS Comprehend Medical Lambda Cognito CloudTrail Terraform GitHub Actions · OIDC

At a glance

124 passing automated tests, run on every PR and push to main
0.001 detection threshold, derived from a stated 1000x cost ratio — not guessed
5 independent IAM resource policies scoped to the same "confused deputy" pattern, recognized and reused

Why it exists

Healthcare has been the costliest industry for data breaches for over a decade, and most PHI exposure happens downstream of the originating hospital — through third-party vendors, analytics platforms, and AI pipelines that received the data secondhand. This pipeline sits at exactly that handoff point: making clinical text safe to share before it leaves the organization that holds it.

It deliberately does not try to build a better PHI detector than AWS already offers. AWS Comprehend Medical's DetectPHI does the entity detection. The engineering problem this project solves is everything around that call: a defensible confidence threshold, a regex backstop for a measured detection gap, an encrypted review path for low-confidence entities, and a security posture that's verified live rather than just written down.

Decisions worth knowing about

Turning a stated principle into a number

The requirements said from day one that a missed identifier is a compliance failure and an over-redacted word is just noise — but that's a stance, not a threshold. It was resolved with a cost-sensitive formula, t* = C_FP / (C_FP + C_FN), using a 1000x cost ratio grounded in Health Canada's clinical-anonymization guidance and confirmed against three rounds of corpus testing on the live API. The math resolves to 0.001 — and the calibration assumption that could break it is stated plainly rather than glossed over.

Closing a measured detection gap without replacing the engine

Comprehend Medical is trained on US clinical text and phone formats. Measured directly: an Australian mobile number in spaced format comes back truncated, and in international format isn't detected at all. A regex backstop for AU mobile formats was layered in and unioned with the API's own entities — closing the measured gap, not attempting to out-detect AWS.

One IAM pattern, recognized and reused five times

S3 → pipeline Lambda, S3 → CloudFront, API Gateway → two separate backend Lambdas, and CloudTrail → its own log bucket all needed the same shape: a resource policy scoped to one caller ARN, not the broader service principal alone. Treating it as one recurring idiom — including resolving a genuine circular dependency on the fifth instance — is what let each subsequent case go in correctly the first time.

A security fix corrected after review, not shipped wrong

The first hardening pass removed a Cognito auth flow, reasoning it closed a refresh-token pathway. Checked against AWS's own documentation: that setting doesn't govern the API family this app actually uses. The real fix — cutting refresh-token lifetime from 30 days to 1 hour — was applied once that was understood, and the change record says so honestly rather than claiming the wrong fix worked.

Audit logging, priced before it was built

Every access-control layer governed whether someone could decrypt a flagged review entity; nothing recorded whether they actually did. CloudTrail pricing was checked against AWS's current rates before designing anything, then scoped narrowly on purpose — one bucket, read events only. Verified live: a real reviewer's access produced a log entry within 5 minutes.

Testing

124 passed, 2 intentionally failing, 1 deselected on the latest verified CI run. The two xfail(strict=True) cases aren't slack in the suite — they pin a known Comprehend Medical limitation so the suite fails loudly, not silently, if AWS ever changes that upstream behaviour. Both handlers that previously had no coverage were checked for whether their tests could actually fail before being trusted, which caught a check that was verifying the wrong thing.

CI/CD

GitHub Actions runs the test suite on every PR and every push to main. From main, the Lambda functions deploy once those tests pass, and the frontend deploys through its own workflow — authenticated via OIDC, with no long-lived AWS keys stored anywhere. Infrastructure changes go through Terraform, by hand, never from CI.

Known limitations — documented, not hidden

  • The AU mobile regex backstop closes the measured formats; it doesn't address the underlying US-centric training bias in Comprehend Medical's phone detection more broadly.
  • Comprehend Medical's ADDRESS entity type produces occasional false positives on phrases like "physiotherapy department" — accepted as noise, consistent with the FR-4 cost-ratio decision.
  • The pipeline Lambda has no on-failure destination; a note that fails every retry is lost with only a CloudWatch error left behind. Recorded as the next item if this ever handles real production volume.
